# Reversible Prolog Tutorial (`rp/1`)

QCLP_G has two subsystems. The constraint compiler (`run`, `solve`,
`export`, ...; see `User_Guide.md`) turns `.clp` problems into Grover
circuits. This tutorial covers the other one: the **reversible Prolog
compiler**. It takes an ordinary Prolog predicate and compiles it to
microcode, runs it in an interpreter to check the arithmetic, and
exports it as an OpenQASM 3.0 reversible circuit.

The constraint compiler is built on it: Grover oracles are made from the
same adders, XOR blocks and comparators.

This subsystem keeps its original name in code: the command is `rp/1`
and the core module is `rp_engine.pl` (formerly `rprolog.pl`; QCLP_G was formerly RProlog).

## Setup

Start SWI-Prolog in the `QCLP_G` directory and load the package:

```
swipl --stack_limit=256M
?- [load].
```

`rp(help)` lists the commands below. Predicates you write yourself (the
half adder, majority and parity examples) go in a file of your own,
which you load with `[myfile]` before calling `rp/1` on them.

| Subsystem | Entry point | Purpose |
|--------|-------------|---------|
| Reversible Prolog | `rp(...)` | Compile Prolog predicates to reversible circuits (this tutorial) |
| Constraint compiler | `run/1,2`, `solve/1`, `info/1`, `show/1`, `export/1,2` | `.clp` problems to Grover circuits (`User_Guide.md`) |
| Statevector simulator | `qsim_run/1,2` | Simulate any QASM 3.0 circuit |

## The `rp/1` commands

These compile and run ordinary Prolog predicates as reversible circuits.

| Command | Purpose |
|---|---|
| `rp(show(Goal))` | Compile and display microcode + Layer 2 QASM |
| `rp(run(Goal, Inputs))` | Run the interpreter, print variable bindings |
| `rp(run(Goal, Inputs, Theta))` | As above, but also binds `Theta` for post-run decoding |
| `rp(decode(Theta, Var, Val))` | Extract a single named variable's value from a `Theta` |
| `rp(last)` | Re-display variable bindings from the most recent run |
| `rp(export(Goal, File))` | Write a complete QASM 3.0 file |
| `rp(help)` | Print the command list |

**Inputs** is a list of `VarName-Value` pairs: `[a-0, b-1]`.

**Theta** is the output store returned by `rp(run(..., Theta))` — a list of `Var-Value` pairs covering all named variables (inputs, outputs, and intermediates). Use `rp(decode(Theta, Var, Val))` to pull out individual values, or `rp(last)` to re-display the full binding list if the output has scrolled past.

## Example 1: XOR gate

The simplest reversible operation. Uses the library predicate `rp_xor/3`.

```prolog
?- rp(show(rp_xor(a,b,out))).
```

```
-- Microcode --
  ch(1)
  unf(rp_xor(a,b,out), 1)
  next(out, a xor b)
  exit(rp_xor(a,b,out))

-- QASM --
OPENQASM 3.0;
include "stdgates.inc";
// Generated by QCLP_G

qubit[n] out;
qubit[n] result;

// === compute ===
cx a, out; cx b, out;  // out = a xor b

// === copy output ===
cx out, result;  // copy output

// === uncompute (Bennett) ===
cx a, out; cx b, out;  // out = a xor b
// end
```

The microcode has four events: choose clause, unfold, one arithmetic step,
exit. The QASM uses two CNOT gates to compute, one to copy, two to uncompute.
The uncompute restores `out` to `|0⟩` after the result is copied — Bennett's
reversible computation trick.

## Example 2: Modular addition

Run the interpreter to verify the arithmetic.

```prolog
?- rp(run(rp_mod_add(a,b,15,out), [a-7, b-11])).
```

```
-- Results --
  out = 3
  t1 = 18
  a = 7
  b = 11
```

`t1` is the intermediate value `7+11=18`. `out` is `18 mod 15 = 3`.
The interpreter shows all named variables including intermediates.

## Example 3: Half adder (your own predicate)

Write an ordinary Prolog predicate. No special syntax required.

```prolog
half_adder(A, B, Sum, Carry) :-
    Sum   is A xor B,
    Carry is A /\ B.

?- rp(show(half_adder(a,b,sum,carry))).
```

```
-- Microcode --
  ch(1)
  unf(half_adder(a,b,sum,carry), 1)
  next(sum, a xor b)
  next(carry, a/\b)
  exit(half_adder(a,b,sum,carry))
```

Now run it with `a=1, b=1`:

```prolog
?- rp(run(half_adder(a,b,sum,carry), [a-1, b-1])).
```

```
-- Results --
  carry = 1
  sum = 0
  a = 1
  b = 1
```

1 AND 1 = 1 (carry). 1 XOR 1 = 0 (sum). Correct.

## Example 3b: Decoding run results

After `rp(run(...))`, use the 3-argument form to capture the full output
store and decode individual variables:

```prolog
?- rp(run(half_adder(a,b,sum,carry), [a-1, b-1], T)).

-- Results --
  carry = 1
  sum = 0
  a = 1
  b = 1

?- rp(decode(T, carry, C)).
C = 1.

?- rp(decode(T, sum, S)).
S = 0.
```

`rp(last)` re-displays the full binding list if the output has scrolled:

```prolog
?- rp(last).

-- Last Results --
  carry = 1
  sum = 0
  a = 1
  b = 1
```

## Example 4: Majority vote

Three-input majority: output is 1 if at least two inputs are 1.

```prolog
majority(A, B, C, Out) :-
    T1  is A /\ B,
    T2  is B /\ C,
    T3  is A /\ C,
    T4  is T1 \/ T2,
    Out is T4 \/ T3.

?- rp(run(majority(a,b,c,out), [a-1, b-1, c-0])).
```

```
-- Results --
  out = 1
  t4 = 1
  t3 = 0
  t2 = 0
  t1 = 1
  a = 1
  b = 1
  c = 0
```

Two of three inputs are 1, so output is 1.

## Example 5: Byte parity

Compute the parity of 8 bits (XOR of all bits).

```prolog
byte_parity(B0,B1,B2,B3,B4,B5,B6,B7, Out) :-
    T1 is B0 xor B1,
    T2 is T1 xor B2,
    T3 is T2 xor B3,
    T4 is T3 xor B4,
    T5 is T4 xor B5,
    T6 is T5 xor B6,
    Out is T6 xor B7.

?- rp(run(byte_parity(b0,b1,b2,b3,b4,b5,b6,b7,out),
          [b0-1,b1-0,b2-1,b3-1,b4-0,b5-0,b6-1,b7-1])).
```

```
-- Results --
  out = 1
  ...
  b0 = 1
```

Input `11110011` has five 1-bits (odd), so parity = 1. Correct.

## Example 6: Export XOR to a QASM file

Write a complete, flat-indexed QASM 3.0 file ready for a quantum backend.

```prolog
?- rp(export(rp_xor(a,b,out), 'xor.qasm')).
```

```
Written: xor.qasm  (4-bit)
```

(A relative file name is written to the current directory, and the
`qasm/` directory is created if it does not exist.)

The file uses 20 qubits: `a[0..3]`, `b[0..3]`, `out[0..3]`,
`result[0..3]`, `carry[0..3]`. Only standard `cx` gates — submittable
to IBM Quantum, AWS Braket, or any QASM 3.0 compatible simulator.

## Example 7: Modular exponentiation oracle

Show the microcode for `rp_mod_exp` — the Shor oracle kernel.

```prolog
?- rp(show(rp_mod_exp(2,exp,15,out))).
```

The `ite(...)` event in the microcode is the conditional selection between
the squared accumulator and the multiplied accumulator, controlled by the
extracted exponent bit. When exported, this becomes a Fredkin
(controlled-SWAP) gate network.

---

## Example 8: Changing register width

The default is 4-bit registers. Use `rp_set_bits/1` to change:

```prolog
?- rp_set_bits(8).
?- rp(export(rp_mod_add(a,b,255,out), 'add8.qasm')).
```

This generates an 8-bit modular adder (48 qubits) for 0..255
arithmetic.

## Further commands

```prolog
?- rp_cost_table.       % gate cost reference (T-gates per operation)
?- rp_set_bits(8).      % register width for rp/1 (default 4)
?- rp_get_bits(N).
```

`rp_verify_adder`, `rp_verify_mod(15)` and `rp_verify_mul` also exist,
but they compare Prolog arithmetic with itself (`sim_add(A,B,S) :- S is
A+B`), so they always print "all correct". They do not test the
generated gates. The gate-level checks are in the test suite:
`rp_test` category 1 runs small circuits on the simulator, and
`rp_test(full)` category 7 runs complete Grover circuits and compares
them with theory.

The Shor demo (`rp_shor_demo`, `modexp_k_demo`, and the files
`rp_shor.pl` and `rp_modexp.pl`) is not part of this package.
